# M8 — i18n con Fluent

## Concepto

Ya tenés el contenido separado (M4). Entonces tres idiomas no son tres páginas:
son **tres `Content`** y una función que traduce.

El proyecto ya tiene los archivos `i18n/es.ftl`, `i18n/en.ftl`, `i18n/ca.ftl`.
Fluent (el formato de Mozilla) se ve así:

```ftl
header-home = Inicio
footer-copyright = © 2025 MitDevCat
```

Usá `fluent-templates`, que carga los `.ftl` **en tiempo de compilación**: si te
equivocás en una clave, no compila. Eso es mejor que un error en producción.

```sh
cargo add fluent-templates
```

## El problema real del i18n en grilla

Acá está lo que nadie te cuenta: **"cosas chicas que no se caen" mide 28
caracteres en español. En catalán mide otra cosa. En inglés, otra.**

En CSS no importa: el navegador reacomoda. En una grilla **sí importa**: si la
traducción entra en un ancho y no en otro, se rompe el dibujo.

Tres estrategias, en orden de calidad:

1. **Copy por ancho por idioma.** Sí, es el trabajo más honesto: cada idioma
   tiene su versión corta y su versión larga, y cada una se midió.
2. **Medir y truncar en runtime.** Barato y seguro: si la traducción no entra,
   se corta con `…`. Menos bonito, nunca roto.
3. **Confiar en que entra.** Es la que produce el bug a las tres de la mañana.

En este curso: **1 para el copy corto, 2 como red de seguridad siempre activa.**
El `truncar` de M3 no se saca nunca.

## Ejercicio

1. Un `enum Idioma { Es, En, Ca }` con `slug()` (`"es"`, `"en"`, `"ca"`) y `lang()`
   para el atributo `<html lang>`.
2. `Content::para(idioma) -> Content`, que arma el contenido leyendo las claves
   del `.ftl`.
3. Generar una página por idioma:

```
build/es/index.html
build/en/index.html
build/ca/index.html
```

4. Los links de idioma del pie ahora llevan a rutas reales (`/es/`, `/en/`,
   `/ca/`), y el hit area de M7 tiene que seguir funcionando.
5. Un test por idioma: el render en catalán **no** contiene palabras en español.

## Criterio de aceptación

```rust
#[test]
fn cada_idioma_genera_su_archivo_y_su_lang() {
    for idioma in Idioma::TODOS {
        let html = documento(&Content::para(idioma), idioma);
        assert!(html.contains(&format!("<html lang=\"{}\">", idioma.lang())));
    }
}

#[test]
fn el_catalan_no_habla_en_espanol() {
    let texto = a_texto(&pagina(&Content::para(Idioma::Ca), 100));
    assert!(!texto.contains("cosas chicas"), "quedó texto en español: {texto}");
}

#[test]
fn ninguna_traduccion_rompe_la_grilla() {
    for idioma in Idioma::TODOS {
        for ancho in [40u16, 60, 100] {
            let texto = a_texto(&pagina(&Content::para(idioma), ancho));
            for linea in texto.lines() {
                assert!(linea.chars().count() <= ancho as usize,
                    "{idioma:?} @ {ancho}: {linea:?}");
            }
        }
    }
}
```

Ese último test es el importante: **9 combinaciones** (3 idiomas × 3 anchos) y
ninguna puede romper la grilla. Es el test que convierte "creo que entra" en
"entra".

- [ ] Los tres tests pasan.
- [ ] Los `.ftl` originales se siguen usando (no los reescribiste a mano en Rust).
- [ ] El pie linkea a los tres idiomas y las rutas existen.

## Si te trabás

- `fluent-templates` te da una función de lookup; si una clave no existe, el
  error aparece al compilar. Es una feature, no una molestia.
- Los `.ftl` tienen **una clave por línea**, sin indentación.
- El `<html lang>` no es decorativo: el navegador lo usa para hyphenation y los
  lectores de pantalla para elegir la voz. Cambiarlo cambia la lectura real.

## Qué aprendiste

- i18n es datos, no plantillas duplicadas.
- Que traducir cambia el layout, y en una grilla eso se mide.
- Que los tests combinatorios (idioma × ancho) cuestan cinco líneas y evitan una
  clase entera de bugs.
